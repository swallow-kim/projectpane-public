# 지원 범위와 검증

## 1.3.0 updater 검증 (2026-11-01)

1.3.0 서명 NSIS 빌드를 [정식 릴리스](https://github.com/swallow-kim/projectpane-public/releases/tag/v1.3.0)로 게시했습니다. 제품 커밋은 `c78fc9c27b07cb0545c0292ea489328e8f949c2f`이며 `v1.3.0` 태그가 이 커밋을 가리킵니다. 실제 Tauri updater 2.14.1의 검증 API로 최종 EXE의 서명을 확인했고, 변조된 바이트·서명과 다른 버전·누락된 서명·다운그레이드를 거부했습니다.

게시 후 인증 없는 HTTP로 EXE·서명·버전 JSON·해시 목록을 내려받아 로컬 검증본과 바이트 단위로 비교했습니다. `releases/latest/download/latest.json`도 일치합니다. 별도 이전 버전 합성 호스트에서 실제 updater의 공개 feed 조회·다운로드·서명 검증까지 통과했으며 설치는 실행하지 않았습니다. 최종 EXE는 4,049,535바이트, SHA256은 `bec8e7f747fc9138eff70f421aca7036a054fbcfa484151f2bb79f3c39d2c237`입니다. 공개 저장소에는 Actions workflow가 없으므로 CI 통과로 표현하지 않습니다.

수동 확인·다운로드·설치 분리, ZIP판 설치 차단, 실패 시 설치 비활성화, 프로젝트 저장 ACK와 종료 순서를 확인했습니다. 실제 합성 폴더와 네 개 목록 worker·watch worker를 사용한 종료 검사도 통과했습니다. NSIS의 실제 Restart Manager 검사에서는 정상 종료 인계만 파일 변경 지점에 도달하고, 일반 실행 중 대상 및 종료 시간 초과 대상은 변경 전에 차단했습니다.

추가 격리 검사에서는 실제 플러그인이 로컬 서명 합성 NSIS 프로그램을 실행하고 호스트를 종료한 후, 생산용 가드 통과·호스트 재시작·합성 프로젝트 보존까지 확인했습니다. 실제 Windows 프로세스/설치 API를 사용했지만 전체 제품 GUI의 두 정식 버전 간 설치 시험은 아닙니다. 기존 사용자 앱이 실행 중이어서 종료하거나 교체하지 않았습니다. 이 한계를 숨기지 않고 첫 공개 updater 지원판으로 제공합니다.

설치파일의 worker 중복 포함을 제거했고, 고지 14개와 상대 링크, EXE·worker의 빌드 대응 및 개인 빌드 경로 부재를 검사했습니다. 호스트 EXE의 차이는 Tauri가 NSIS에 넣는 정확한 `UNK`→`NSS` 번들 표식 3바이트만 허용하고 나머지 바이트를 모두 비교했습니다. 공개키를 제외한 개인키·암호·로컬 검사 로그는 배포하지 않습니다.

타입 검사, Vitest 411건, Node 보조 검사 22건, Rust 라이브러리 308건과 desktop 25건, fmt/clippy, 서명 Windows 패키지 빌드를 통과했습니다. 일반 Rust 실행에서 제외된 native 검사는 자동 통과로 계산하지 않으며, 위 worker·서명·합성 인계 검사는 명시적으로 별도 실행했습니다.

브라우저 전체 실행은 256건 통과·3건 실패였습니다. 실패는 압축 메뉴의 첫 행 클릭을 열 제목이 가로챈 시간 초과 1건과, 영역 선택 자동 스크롤이 5초 안에 요구 거리(1,400/2,000px)에 못 미친 2건(774/576px)이었습니다. 제품 코드·assertion·시간 제한을 바꾸지 않고 이 세 항목만 단독 실행하여 모두 통과했습니다. 병렬 실행의 타이밍 민감성은 남으며 정확한 원인은 확정하지 않았습니다. 최초 전체 실행을 259건 통과로 바꾸거나 실패를 삭제하지 않았습니다. 새 updater UI 검사 5건은 최초 전체 실행에서 통과했습니다.

다운로드 서명 실패의 브라우저 검사는 모의 IPC이며 실제 서명 검증과 구분합니다. 공개 후보 544파일의 비밀정보 검사 후보는 0건이고, 개인 개발 경로·기존 비공개 저장소 링크를 찾지 못했습니다. 이는 비밀정보가 절대 없다는 보장은 아닙니다. 기존 사용자 설치본과 실제 클립보드는 사용하지 않았습니다.

## 자동 검사

npm run typecheck, npm test, npm run build, npm run test:browser, Rust fmt/clippy 및 desktop 라이브러리 시험을 사용합니다. 브라우저 검사는 모의 IPC와 합성 목록을 사용하며 실제 파일·클립보드·Explorer 드래그 검증이 아닙니다. Chromium은 별도로 준비합니다.

Rust 파일 작업 시험은 시험 소유 임시 경로를 사용합니다. OS 정책이나 공유 조건으로 실패할 수 있으며 접근 거부를 제품 통과로 해석하지 않습니다. 설치 분기 시험과 데스크톱 관측은 부작용을 확인한 뒤 별도로 실행합니다. 실제 사용자 폴더·현재 클립보드를 시험하지 않습니다.

현재 사본의 결과는 [export 검증 기록](export-validation.md)에 기록합니다. 스크린샷·원시 로그·개인 경로가 포함된 측정 자료는 공개 소스에 포함하지 않습니다.

## 기존 기능의 한계

- 기존 실제 앱 검증은 Windows 10 x64 중심입니다. Windows 11·물리 한국어 IME·Snap·다중 모니터 DPI·실제 Explorer/클립보드 왕복은 미완료입니다.
- Windows↔WSL 복사와 같은 WSL 배포판·볼륨 안 rename 이동은 과거 합성 파일·실제 앱 IPC로 검증했습니다. 이번 export에서 실제 WSL 시험을 반복하지 않습니다.
- 외부 MOVE 기반은 시험 전용이며 제품에서 비활성입니다. Windows↔WSL 이동을 임의로 켜지 않습니다.
- 이전 제품의 연속 8시간 기능 검사는 통과했습니다. 이번 사본이나 후속 변경의 새 8시간 통과를 의미하지 않습니다.
- 일반 4폴더·총 1만 항목은 약 235 MiB였으나, 10만 항목 폴더 반복 탐색 후 265~289 MiB로 250 MiB 목표를 초과한 기록이 있습니다. 부하 조건이 다르며 대용량 반복 메모리 문제는 알려진 이슈입니다. 확정적 누수 입증이나 메모리 목표 전체 통과로 해석하지 않습니다.
- 충돌·실패·취소·부분 성공·불명 결과를 구분합니다. 취소는 Undo가 아니며 불명 작업은 자동 재실행하지 않습니다.

설치 수명·지원 OS·네이티브 입력·배포 고지 검증은 빌드와 구분합니다. 과거 비공개 CI의 결제 제한은 코드 실패나 공개 CI 성공으로 해석하지 않습니다. 설치·보안 정책 변경·새 장시간 관측은 export 검사에 포함하지 않습니다.
